# Timeline

Phased delivery, sequenced so testing lands early and each phase produces something Meridian's team can see and use — not one large delivery at the end.

| Phase | Weeks | Deliverable |
|---|---|---|
| **0 — Onboarding & Architecture Review** | 1 | Current-state architecture review (R4 draft), environment setup, confirmation of scope assumptions with Tanaka's ops team and IT. |
| **1 — Test Foundation (R3)** | 2 | Automated browser test coverage for the Reports and Restocking flows (Restocking tests land alongside Phase 3, written against the new view as it's built). IT sign-off on the testing approach before further changes ship. |
| **2 — Reports Remediation (R1)** | 2 | Reports page brought in line with the rest of the app: filtering restored, shared API client adopted, translations added, debug logging removed. Demo to Tanaka's team. |
| **3 — Restocking View (R2)** | 3 | New Restocking view and backend support, purchase-order recommendations from stock, demand, and operator-entered budget ceiling. Test coverage from Phase 1 extended to cover it. |
| **4 — Documentation & Handoff (R4 final)** | 1 | Finalized architecture documentation incorporating everything built in Phases 1–3. |
| **Stretch (D1–D3)** | as time allows | UI brand alignment, remaining i18n coverage, dark mode — pursued in parallel or after Phase 4 if the fixed-fee budget allows; not sequenced ahead of any required item. |

**Total: ~9 weeks for required scope (R1–R4).** Desired items (D1–D3) are treated as stretch goals within the fixed fee, not committed dates — called out explicitly so expectations are set going in, not discovered at the end.
