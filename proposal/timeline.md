# Timeline

Phased delivery, sequenced to match Meridian's stated priorities. Required scope (R1–R4) is committed within a ~10–12 week engagement; desired scope (D1–D3) follows only if time and budget allow within the fixed fee.

| Phase | Weeks | Scope | Notes |
|---|---|---|---|
| 0 — Onboarding & Architecture Review | 1–2 | R4 | Review current system, deliver architecture documentation for Meridian IT. Unblocks everything after it. |
| 1 — Reports Remediation | 2–4 | R1 | Audit and resolve the ~8 logged defects (filters, i18n, data patterns). |
| 2 — Restocking Recommendations | 4–8 | R2 | Largest build: new view, budget-ceiling input, purchase order recommendation logic. |
| 3 — Automated Browser Testing | 8–10 | R3 | End-to-end coverage for core dashboard, Reports, and Restocking. Written incrementally alongside Phases 1–2 where practical, hardened here. |
| 4 — Stretch (if time/budget allow) | 10–12 | D1, D2, D3 | UI refresh, extended i18n, dark mode — priced and scheduled as options, not commitments. |

**Milestones we'd propose confirming with Meridian:**
- End of Phase 0: architecture doc reviewed and accepted by IT
- End of Phase 1: Reports sign-off from R. Tanaka's team
- End of Phase 2: Restocking demo and acceptance
- End of Phase 3: test suite handoff, IT confirms it unblocks their change-approval process

**Assumption:** timeline assumes Meridian stakeholders (Tanaka's team, IT) are available for review/acceptance at each phase boundary within 3–5 business days; delays in feedback shift the schedule accordingly.
