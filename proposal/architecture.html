Technology Stack

A lightweight two-tier application: a single-page Vue frontend talking to a Python API over HTTP. There is no database — the backend serves data from JSON files held in memory, which keeps the system simple but limits concurrency and persistence.

Frontend

Vue 3 + Vite
Composition API, served on port 3000. Axios for HTTP. State shared via composables.

Backend

FastAPI (Python)
ASGI app in server/main.py on port 8001. Pydantic models validate every response.

Data Layer

JSON Files
Seven files in server/data/ loaded by mock_data.py into memory. No database engine.

Internationalisation

en / ja
Custom useI18n.js composable. Currency auto-switches USD ↔ JPY with locale.

Layered Architecture

A request originates in the browser, flows down through the Vue presentation layer and the centralised API client, crosses the network to FastAPI, and resolves against the in-memory data layer. The response travels back up the same path.

Data Flow Walkthrough

A typical interaction — a user changing the warehouse filter on the Inventory view — traverses the stack as follows.

User changes a filter in the UIThe FilterBar updates a shared ref (e.g. selectedLocation) inside the useFilters composable. Because the refs are module-level singletons, every view sees the change.
View reads current filter stateThe view calls getCurrentFilters() to collect period, warehouse, category and status into a plain object.
api.js builds the requestThe centralised client maps the filter object to query parameters and issues an axios GET against the FastAPI base URL.
FastAPI route handles the requestThe matching route receives the query params and delegates to shared helpers such as apply_filters() and filter_by_month().
In-memory filtering & validationHelpers filter the data loaded by mock_data.py; results are validated and serialised through Pydantic models before leaving the server.
Vue renders the responseThe JSON resolves into reactive refs; computed properties derive display values and the DOM re-renders automatically.

Known Issues & Tech Debt Inherited

Findings from reviewing what the previous vendor left. These are the basis for the remediation work in this engagement (notably requirement R1, Reports remediation).

High Reports view diverges from the rest of the app

Reports.vue is the only view still written with the legacy Options API. It calls axios directly against a hardcoded URL instead of routing through api.js, carries leftover console.log statements, and has no i18n coverage (hardcoded English strings).

Status: currently being remediated under R1.

High Write endpoints declared but not implemented

api.js declares POST, PATCH and DELETE methods for tasks and purchase-orders, but main.py implements no such routes. Any call to them returns 404. Either the client surface or the server needs to catch up.

Status: relevant to the new restocking feature (R2), which needs real purchase-order creation.

Medium Category casing mismatch (latent coupling)

FilterBar emits category values in lowercase, while the underlying data is Title Case. It works only because the backend silently lowercases before matching — a fragile, undocumented contract that will break the moment either side changes.

Low Hardcoded Dashboard KPIs

Some KPI values on the Dashboard are hardcoded rather than computed from live data, so they will not respond to filters or reflect real figures.
