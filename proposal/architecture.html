System Layers

The application is a two-tier web app: a Vue 3 single-page application served by Vite (port 3000) communicating with a Python FastAPI backend (port 8001) over HTTP. There is no database — all data lives in JSON files loaded into memory at startup.

Filter Data Flow

The four global filters (Time Period, Warehouse, Category, Order Status) propagate from the UI through to the backend via a shared composable and URL query parameters.

Known Constraints & Limitations

Inherited from the previous vendor or identified during the R1 audit. Fixed items are resolved as part of this engagement.

Fixed in this engagement Known limitation
Reports filters not wired up
Reports page ignored all global filters — data never reloaded on filter change. Both frontend (no watch) and backend (no query params) were incomplete. Fixed in R1.
Reports: Options API + direct axios
Reports.vue was the only view using Options API and calling axios directly instead of api.js, diverging from the established patterns in all other views. Migrated to Composition API in R1.
No database — JSON only
All data is loaded from flat JSON files at server startup. Changes do not persist across restarts. No CRUD endpoints exist despite Pydantic models being defined for them.
Spending data is static
The /api/spending/* endpoints return pre-aggregated JSON, not values computed from orders or transactions. Spending figures do not respond to warehouse/category filters.
Dashboard KPIs partially hardcoded
Inventory Turnover Rate (4.2) and Avg Processing Time (2.8) are static values in Dashboard.vue. The backend does not provide these metrics — they require COGS data and delivery-date calculations not available in the current data model.
No authentication
CORS is fully open and there is no API authentication. This is acceptable for an internal, locally-hosted deployment but must be addressed before any external exposure.
