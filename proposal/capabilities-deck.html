Requirement R1

Reports Module Remediation

We conduct a structured audit across four defect areas before writing a single line of fix code:

  • Filter wiring — query param flow end-to-end
  • i18n gaps — untranslated strings in templates
  • API pattern inconsistencies — Options vs. Composition API
  • Console noise — unhandled errors and warnings
Our Commitment

"At least eight issues" is a floor, not a ceiling. We document every finding before touching code. Each fix is committed separately so Meridian IT can trace every change.

Gate

Operations team confirms Reports behaves correctly across all filter combinations.

Requirement R4

Architecture Documentation

Produced immediately after R1 — while the codebase is freshest in our heads.

Deliverable 1

Interactive HTML Diagram

Visual map of Vue views, API client layer, FastAPI routes, data layer, and filter/reactivity patterns. Self-contained file — no tooling required to open.

Deliverable 2

Written Narrative

Layer-by-layer description of responsibilities, data flow, and inherited design decisions. Written for Meridian IT — assumes web familiarity, not codebase knowledge.

This document also serves as our own onboarding artifact for Phase 3 — reducing R2 design risk.

Requirement R2

Restocking Recommendations

How It Works
  • Operations staff enters a budget ceiling
  • System combines current stock levels with demand forecast
  • Ranked purchase order recommendations returned
  • Filter by warehouse or product category
Frontend

New RestockingView.vue — budget input, recommendations table. Composition API, consistent with remediated codebase.

Backend

New /api/restocking endpoint — combines /api/inventory + /api/demand, applies budget constraint, returns ranked results.

Requirement R3

Automated Browser Testing

Written last — so the test suite covers the complete, final application: legacy flows and the new Restocking feature.

Tool

End-to-end browser tests. Already configured in Meridian's repo.

Coverage

All Critical Flows

Inventory, Orders, Spending, Reports (including R1 filter interactions), Restocking.

Outcome

IT Green-Gate

A single passing test suite that IT can run on any proposed change before approving it.

Optional Extensions

D1–D3: When You're Ready

D1 · +2 weeks

UI Modernization

Component-level refresh aligned to a modern dashboard reference (clean card layout, KPI tiles, blue/slate palette). Mockup for approval before any implementation.

D2 · +1 week

Internationalization

Full i18n coverage for remaining modules. Japanese (ja) locale for the Tokyo warehouse team. Scope confirmed during R1 audit.

D3 · +1 week

Dark Mode

Operator-selectable theme via CSS custom properties. Designed for low-light warehouse floor stations. Persistent across sessions.

Extensions can be activated at any milestone gate and run in parallel with Phase 4 testing to avoid sequential delay.
