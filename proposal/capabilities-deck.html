Modernizing the Meridian Components
Inventory Dashboard

A response to RFP MC-2026-0417 — remediating, extending, and hardening the operations dashboard your team relies on every day.

The Situation

A capable system, left unfinished

  • The 2024 vendor delivered a working Vue / FastAPI dashboard covering inventory, orders, and spend — then the contract ended with work in progress.
  • The Reports module has known, unresolved defects — filters, translations, inconsistent data.
  • There's no way today to turn stock levels and demand into a purchasing decision.
  • With zero automated test coverage, IT has been unwilling to approve further changes at all.

Our Philosophy

Extend what works. Fix what's broken. Don't rebuild what doesn't need it.

  • We work inside the existing Vue 3 / FastAPI application — no rewrite, no new framework.
  • Required scope is delivered as committed, fixed-fee work.
  • Desired scope is priced separately, so it's never traded off against what's mandatory.
  • We document and test as we go, so what we leave behind outlasts our engagement.
Approach — Phase 0

Understand before we touch anything

We start with a full architecture review of the current system — not because it's ranked last in the RFP, but because every other phase depends on it. The output is current-state documentation Meridian IT can use long after our engagement ends.

Approach — R1

Reports: audit and fix in place

We audit the Reports module against Meridian's logged defects plus anything surfaced during architecture review, and resolve them using the application's existing filter → API → computed-property pattern — no new pattern introduced just for this module.

Approach — R2

Restocking: the biggest build

A new view turning stock levels, demand forecast, and an operator-supplied budget ceiling into recommended purchase orders. Rule-based and transparent — a decision-support tool, not a black-box forecasting model.

Approach — R3

Testing: unblock IT, on the flows that matter

End-to-end browser coverage for the core dashboard, Reports, and Restocking — the three areas of highest change and highest operational risk. Enough for IT to start approving changes again.
