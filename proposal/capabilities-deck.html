Our Approach

Stabilize first, then extend

We don't build new capability on top of a foundation we don't trust yet. Every phase below produces working, demonstrable output — Meridian doesn't wait until the end to see progress.

Phase 0 · Weeks 1–3

Foundation

Data layer migration

Migrate off flat JSON files to a proper database, one-to-one, with no behavior change — before anything new is built on top of it. Architecture documentation begins alongside this work.

Phase 1 · Weeks 4–7

Stabilize & unblock

Reports remediation + testing infrastructure

Resolve the Reports module's logged defects and stand up automated browser testing alongside the fix — so IT gets a working example of test coverage on day one, not a promise for later.

Phase 2 · Weeks 8–13

Build

Restocking recommendations

The largest net-new capability in this engagement: stock levels + demand forecast + operator-supplied budget ceiling → recommended purchase orders. Covered by the same automated testing introduced in Phase 1.

Phase 3 · Weeks 14–16

Polish

UI refresh, i18n expansion, dark mode

Desired items (D1–D3), scoped to fit remaining time and budget without displacing required work. First to trim if constraints require it.
