Our Understanding

You inherited a system that works — but was never finished

  • A capable Vue/Python dashboard your operations team uses daily across SF, London, and Tokyo
  • The Reports module has known, unresolved defects
  • No automated test coverage — so IT can't safely approve changes
  • The capabilities Operations most wants — intelligent restocking — were never built
The Core Problem

The missing test coverage is the quiet center of it all

Without tests, IT can't tell whether a change breaks something — so they freeze approvals. The system stays half-finished because nothing can safely move.

Any credible modernization has to start by making the system safe to change.

Phase 1 · Foundation (R3 + R4)

First, we make the system safe to change

  • R3 — Automated browser testing: Playwright E2E coverage across the full critical operator path, ready to wire into CI
  • R4 — Architecture documentation: a current-state overview built from the real code, for IT handoff
  • This is the lever that converts a change-averse IT function into one that can approve with confidence
Phase 2 · Finish (R1)

Then we fix Reports — completely

  • Audit, then remediate: catalogue every defect, agree a definition of done, then fix
  • Addresses all three logged classes — filter behavior, i18n gaps, data/pattern inconsistencies
  • Every fix lands with a regression test that proves it stays fixed
Under a not-to-exceed ceiling — Meridian carries zero overrun risk.
Phase 3 · Extend (R2)

Then we build Restocking — the feature Operations is waiting for

  • Recommends order quantities to cover demand across supplier lead time — not a static threshold
  • Flags items that will stock out before a replenishment PO can arrive
  • Fits recommendations within an operator-supplied budget ceiling, prioritized by urgency
  • Early working demo mid-phase, so Operations shapes it before it hardens
