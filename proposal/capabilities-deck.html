The situation

A capable system with unfinished work

Meridian's current dashboard was delivered by a previous vendor in 2024. It covers core inventory, orders, and spending — but it left the contract with known defects, no test coverage, and several capabilities the operations team has been waiting for.

  • Reports module — at least eight known defects; filters not fully wired up
  • No automated tests — Meridian IT has frozen deployments as a result
  • Missing features — Restocking recommendations are the top ask from operations
  • Incomplete migration — parts of the codebase on older patterns the previous vendor didn't finish

Our approach

Audit first. Build on solid ground.

We don't commit to defect counts before we've read the code. The previous vendor's handoff notes list three known issues in the Reports module; the RFP cites at least eight. That gap is a reason for caution, not confidence.

  • Phase 1 is audit and test harness — no fixes until we know exactly what we're fixing
  • Tests are written per phase — not retrofitted at the end; IT can approve work incrementally
  • Meridian's priority order — R1 → R2 → R3 → R4; we follow their sequence, not ours
  • Two milestone sign-offs mid-engagement — Reports review with operations before we move to Restocking
Requirement R1

Reports module remediation

What we'll do
  • Full defect catalogue before any fixes
  • Triage by severity — broken behaviour first, then data inconsistency, i18n gaps, pattern debt
  • Resolve all Options API remnants in the Reports view
  • Playwright tests written for each fixed flow
Deliverable
  • Fully functional Reports module
  • All filters wired and consistent with API patterns
  • No console errors in normal operation
  • Passing test suite for all Reports flows
Requirement R2

Restocking recommendations

How it works
  • New view within the existing application — same stack, same data flow patterns
  • Inputs: current stock levels, demand forecast, operator-supplied budget ceiling
  • Output: prioritised purchase order recommendations within budget
Our process
  • Requirements conversation with Tanaka's team before writing code
  • Confirm: budget scope (per warehouse or global?), demand weighting, output format
  • Build, test, demo — sign-off before handoff
Requirement R3

Automated browser testing

The absence of test coverage is why Meridian IT has frozen deployments. We treat R3 as a foundation, not an afterthought — the test harness goes in during Phase 1, before any code changes.

  • Tool: Playwright — well-suited to Vue, strong CI integration, readable output
  • Scope: all major flows — inventory, orders, reports, restocking
  • Approach: tests written per phase alongside each feature; IT can review and approve incrementally
  • Deliverable: complete test suite with documentation for running locally and in CI
